# PRD: 팀 프로젝트 팀 편성 웹 앱

## 1. 목적
학생들이 팀 프로젝트의 팀을 스스로 편성한다. 학생은 팀에 지원하고 팀원은 투표로 받아들인다. 모집을 마감한 뒤 남은 학생은 AI가 배정안을 내고, 앱이 그 배정안을 규칙으로 검사해 통과한 것만 관리자가 확정한다.

## 2. 사용자
| 사용자 | 하는 일 |
|---|---|
| 학생(명단 CSV의 가상 학생) | 학번과 비밀번호(1234)로 로그인, 팀 목록·팀원·역할 보기, 팀에 지원, 내 팀에 들어온 지원에 찬성/거부 |
| 관리자(학번 `admin`) | 명단 CSV와 팀 수로 처음 상태 만들기, 모집 마감, AI 배정, 배정안 확정 |

관리자 계정은 앱이 시작할 때 비밀 값 `ADMIN_PASSWORD`로 만들거나 비밀번호를 갱신한다. 명단을 다시 올려도 남는다.

## 3. 규칙
- 역할 6개: 기획자, 웹 프로그래머, 프론트엔드 디자이너, 테스터, 보고서 작성자, 발표자. 학생마다 주 역할 1개, 보조 역할 0~2개(바꾸지 않음).
- 확정한 팀은 2~4명, 빈 팀 없음.
- 한 팀에 주 역할이 같은 학생 2명 이상 금지(보조 역할은 이 검사에 쓰지 않음).
- 모든 팀에 기획자와 웹 프로그래머를 맡을 학생이 서로 다른 사람으로 1명씩(주 역할 또는 보조 역할).

### 3.1 지원과 투표
| 상황 | 결과 |
|---|---|
| 빈 팀에 지원 | 바로 승인 |
| 팀원이 있는 팀에 지원 | 대기. 투표하는 때의 팀원 모두가 투표 |
| 한 명이라도 거부 | 바로 거절 |
| 모든 팀원이 찬성 | 승인 직전 규칙 재검사 → 통과하면 승인, 어기면 거절 |
| 막힘(접수하지 않음) | 모집 마감, 이미 팀이 있음, 결과를 기다리는 지원이 있음, 팀이 꽉 참, 같은 주 역할의 팀원이 있음, 필수 포함 역할을 맡을 학생의 자리가 모자람 |

필수 포함 역할 자리: 지원자가 들어간 뒤 남는 자리 수가 그 팀에서 아직 채우지 못한 필수 포함 역할 수보다 적으면 막는다. 한 학생이 기획자와 웹 프로그래머를 둘 다 할 수 있어도 하나로만 센다.

### 3.2 마감과 배정
1. 마감: 대기 지원은 거절, 1명뿐인 팀의 학생은 팀에서 빠짐.
2. AI 배정: 지금의 팀 구성, 팀이 없는 학생과 역할, 규칙을 오픈라우터 모델에 보내 배정안을 받음. 이미 팀에 있는 학생은 옮기지 않음.
3. 검사 다섯 가지: 빠짐없이 배정, 한 학생은 한 팀에만, 모든 팀 2~4명, 주 역할 중복 없음, 필수 포함 역할 충족.
4. 실패(응답 없음, 빈 응답, 오류, 검사 실패)면 2차, 3차 모델. 모델마다 부른 때부터 120초가 넘으면 끊음.
5. 3차까지 실패하면 앱이 모든 경우를 따져 검사를 통과하는 배정을 찾음.
6. 규칙을 지키는 배정이 아예 없으면 AI를 부르지 않고 "규칙을 지키는 배정이 없음"과 이유를 보여 줌.
7. 검사를 통과한 배정안만 보여 주고, 관리자가 확정하면 DB에 저장.

## 4. 화면
- 로그인: 학번, 비밀번호, 로그인 단추.
- 학생: 로그인한 사람, 결과 안내, 팀 목록(내 팀 표시, 팀원과 역할), 팀마다 지원 단추, 내 팀에 들어온 지원과 찬성/거부 단추, 이미 투표했으면 "내 투표: 찬성".
- 관리자: 명단 올리기(CSV, 팀 수), 모집 마감, AI 배정, 진행 안내(몇 차 모델을 기다리는 중인지와 경과 시간), 배정안 표, 확정, 팀이 없는 학생, 팀 구성.
- 화면 요소의 key 는 공고 2.7절의 표를 그대로 씀(`login_student_no`, `result`, `team_1`, `apply_1`, `vote_yes_{학번}` …).
- 결과 안내는 "승인", "대기", "거절", "막힘" 가운데 하나로 시작.
- 다른 사람의 변경은 3초마다 바뀐 부분만 자동으로 다시 그림.

## 5. 고른 해결 방법(공고 3장)
모든 기능을 어려운 해결로 만든다.

| 기능 | 해결 |
|---|---|
| 다른 사람의 변경 보기 | `st.fragment(run_every=3)` 로 바뀐 부분만 자동 갱신 |
| 필수 포함 역할을 지킬 수 없는 팀 | 지원 단계에서 자리가 모자라게 되는 지원을 막음 |
| 같은 팀에 대기 중인 지원이 여럿 | 모든 팀원이 찬성한 순간(투표가 끝난 순서) 규칙을 다시 검사 |
| 마지막 자리에 두 명이 동시에 | `tf_members` 의 `(team_id, slot_no)` 기본 키와 `student_id` 유일성 제약 |
| AI 응답이 늦을 때 | 모델마다 전체 120초를 재서 끊고 다음 모델로 |
| 3차 모델까지 실패 | 검사 다섯 가지를 통과하는 배정을 모든 경우를 따져 찾음 |
| AI 대기 중 화면 | 몇 차 모델의 응답을 기다리는지와 경과 초를 보여 줌 |
| DB 일시정지 막기 | GitHub Actions 예약 작업으로 매일 DB에 질의 |

## 6. 보안과 운영
- 오픈라우터 키, DB 주소, 관리자 비밀번호는 `.env`(로컬)와 Streamlit Secrets(배포)에만 둔다. 화면에는 "있음/없음"만 보여 준다.
- 비밀번호는 bcrypt 해시로 저장한다.
- 관리자 기능은 서버 쪽에서 관리자 여부를 다시 확인한다.
- 테이블 이름은 모두 `tf_` 로 시작한다.
- 화면에 보이는 시각은 한국 시각으로 바꿔 보여 준다.

## 7. 범위 밖
구글 로그인, 학생이 역할을 바꾸는 기능, 투표 바꾸기, 이미 팀에 있는 학생 옮기기.
